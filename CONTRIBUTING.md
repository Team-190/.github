# Contributing to Team 190 repositories

Thanks for helping out! This guide applies org-wide unless a specific repo's own `CONTRIBUTING.md` overrides it.

## Getting started

1. Fork or clone the repo (team members with write access can branch directly).
2. Create a feature branch off `main`: `git checkout -b feature/short-description`.
3. Make your changes, following the code style already used in that repo.
4. Test your changes locally before opening a pull request — see the repo's README for how to build/run it.

## Branching & commits

- Branch names: `feature/...`, `fix/...`, or `chore/...` describing the change.
- Write commit messages that explain *why*, not just *what*.
- Keep pull requests focused — one logical change per PR is easier to review than a large mixed one.

## Pull requests

- Fill out the pull request template.
- Link any related issue.
- Request a review from a mentor or a lead for that subsystem (programming, CAD tooling, etc.) before merging.
- CI must pass before merging to `main`.

## Reporting bugs / requesting features

Open an issue using the appropriate issue template (bug report or feature request). Include enough detail (steps to reproduce, expected vs. actual behavior, robot/season context) for someone else to act on it.

## Code of Conduct

By participating, you're expected to uphold our [Code of Conduct](CODE_OF_CONDUCT.md).
